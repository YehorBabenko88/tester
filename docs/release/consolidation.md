# Consolidation and branch cleanup

Run `python scripts/repository_inventory.py --repo . --github-repository YehorBabenko88/tester --output <final-artifact-directory>/repository-inventory.json` on the final integrated revision. Keep the final report outside Git so that it can describe the final SHA without introducing a self-referential commit. The committed report is a clearly identified historical snapshot. The report enumerates every tracked path, static imports, text/installer/workflow/test consumers, broken local documentation links and branch tips. Dynamic dependencies remain REVIEW_REQUIRED; absence of a static reference never proves dead code.

Classification vocabulary: KEEP retains active functionality and useful regression/evidence; MIGRATE requires a replacement and updated consumers; REPLACE marks obsolete entrypoints with a canonical replacement; DELETE requires proved consumers, equivalent replacement and post-removal regression evidence; REVIEW_REQUIRED records uncertainty. No file is automatically deleted by the audit.

Legacy Preview installers are REPLACE candidates for the signed `Setup-Tester.ps1` route. They retain migration/physical-acceptance consumers and must not be removed solely because a newer filename exists. Old workflow and evidence files preserve accepted historical behavior until replacement coverage passes. Four proved obsolete source entrypoints were deleted: app.py and the Preview installer/history/readiness PowerShell scripts. Their exact names, baseline blob hashes, consumers and replacement evidence are recorded in cleanup-proof.json. The exact original screener range function remains only as a regression reference; all four existing range tests remain. The now-unused Streamlit, pandas and Plotly dependencies were removed. Legacy core/database tests and the Preview migration guard pass before and after removal. Existing scripts with active installer/test consumers remain until those consumers can safely migrate.

The branch report records each exact tip and commits not reachable from the candidate. A zero count proves ancestor history preservation, not necessarily that the branch's intended behavior remains accepted. A nonzero count requires `git log candidate..branch`, `git diff candidate...branch` and `git cherry candidate branch` inspection plus consumer/regression evidence before any deletion proposal. PR snapshots preserve number, state, base/head, exact head SHA, merge date and URL; a missing/limited snapshot cannot establish complete hosted history.

After independent GO and merge to main: refresh all refs and PRs, regenerate inventory against final main, identify ancestor-only branches, review cherry-equivalent and unique histories, retain evidence/unfinished/unique functionality, list exact approved branch names and SHAs, then request owner approval for those exact remote deletions. Recheck tips immediately before action. Never force push, rewrite history, delete unique code or infer authorization from this plan.

The hosted audit paginates tags, releases, deployments and all PRs. Branch entries retain exact tag/deployment/PR base-and-head reference consumers. Unavailable API data is NOT_VERIFIED with a null item list, rather than a fabricated empty verified list. Hosted deployment records do not establish the current state of ADMINIT or any installed service. The inventory records local tags and observed workflow paths/paths-ignore lists, retaining inline forms for review. Event and job conditions require additional review before workflow retirement.

Network adapters are explicitly distinguished in network_contracts: legacy bybit.py remains consumed by engine/core regression and requires migration; standalone bybit_history.py has a different raw_market/ingest_ranges schema and needs data/functionality equivalence before retirement; active catalog acquisition has a single-attempt streaming/TLS/scheduler contract; historical ingest owns shared throttling and bounded retry. Static retention is not evidence that these are one HTTP implementation, nor permission to merge their different retry policies without tests.
