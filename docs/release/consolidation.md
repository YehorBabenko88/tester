# Consolidation and branch cleanup

Run `python scripts/repository_inventory.py --repo . --github-repository YehorBabenko88/tester --output <final-artifact-directory>/repository-inventory.json` on the final integrated revision. Keep the final report outside Git so that it can describe the final SHA without introducing a self-referential commit. The committed report is a clearly identified historical snapshot. The report enumerates every tracked path, static imports, text/installer/workflow/test consumers, broken local documentation links and branch tips. Dynamic dependencies remain REVIEW_REQUIRED; absence of a static reference never proves dead code.

Classification vocabulary: KEEP retains active functionality and useful regression/evidence; MIGRATE requires a replacement and updated consumers; REPLACE marks obsolete entrypoints with a canonical replacement; DELETE requires proved consumers, equivalent replacement and post-removal regression evidence; REVIEW_REQUIRED records uncertainty. No file is automatically deleted by the audit.

Legacy Preview installers are REPLACE candidates for the signed `Setup-Tester.ps1` route. Four obsolete source entrypoints were deleted first: app.py and the Preview installer/history/readiness PowerShell scripts. The now-unused Streamlit, pandas and Plotly dependencies were removed at the same time. Their exact names, blob hashes and replacement evidence are recorded in cleanup-proof.json. The screener reference and root legacy regressions that were then kept were later removed by PR #102 (see below), so they no longer exist in the tree.

The branch report records each exact tip and commits not reachable from the candidate. A zero count proves ancestor history preservation, not necessarily that the branch's intended behavior remains accepted. A nonzero count requires `git log candidate..branch`, `git diff candidate...branch` and `git cherry candidate branch` inspection plus consumer/regression evidence before any deletion proposal. PR snapshots preserve number, state, base/head, exact head SHA, merge date and URL; a missing/limited snapshot cannot establish complete hosted history.

After independent GO and merge to main: refresh all refs and PRs, regenerate inventory against final main, identify ancestor-only branches, review cherry-equivalent and unique histories, retain evidence/unfinished/unique functionality, list exact approved branch names and SHAs, then request owner approval for those exact remote deletions. Recheck tips immediately before action. Never force push, rewrite history, delete unique code or infer authorization from this plan.

The hosted audit paginates tags, releases, deployments and all PRs. Branch entries retain exact tag/deployment/PR base-and-head reference consumers. Unavailable API data is NOT_VERIFIED with a null item list, rather than a fabricated empty verified list. Hosted deployment records do not establish the current state of ADMINIT or any installed service. The inventory records local tags and observed workflow paths/paths-ignore lists, retaining inline forms for review. Event and job conditions require additional review before workflow retirement.

Network adapters: `src/ingest` owns public historical ingestion with shared throttling and bounded retry, and the catalogue acquisition keeps its own single-attempt streaming/TLS/scheduler contract. These are not one HTTP implementation. Do not merge their retry policies without tests.

## PR #102 consolidation (commit `07187ab`, merge `22493c8`)

PR #102 fast-forwarded main to the green release candidate (`d6059af`) and then removed 474 tracked paths. `git diff --diff-filter=D --name-only d6059af 07187ab` lists them all:

- The legacy root prototype `bybit.py`, `bybit_history.py`, `engine.py` and `db.py`, with the root regressions that only exercised it (`test_core.py`, `test_ingest_integrity.py`, `test_postgres_integration.py`, and `test_screener.py` with `tests/platform/reference/legacy_screener.py`), plus `contract_checks/` and `requirements.txt`. None of these were part of the release payload. Their replacement is `src/ingest` (public historical ingestion, `python -m src.ingest`) on top of `src/storage`. The other root unit tests moved unchanged to `tests/unit`.
- The MASTER pinned-wave workflows and scripts (`master-current-runtime-candidate`, `master-disposable-compose`, `master-pending-blob-review`). These only re-verified historical integration waves.
- Historical evidence trees: `docs/coordination`, `docs/adminit-acceptance`, `docs/physical-test`, `docs/evidence` and `docs/superpowers`.

At `d6059af` this document and `scripts/repository_inventory.py` classified `bybit.py` and `bybit_history.py` as MIGRATE. That classification required equivalence evidence between `raw_market`/`ingest_ranges` and the `src/ingest`/`tester_storage` pipeline. **That equivalence evidence was not produced.** The files were removed because nothing in the shipped product consumed them. Any data in an external `raw_market`/`ingest_ranges` database is not migrated by TESTER. The deletion rows and blob hashes are in cleanup-proof.json (`removed_in_pr102`).

The PR #102 body and the message of `07187ab` say the removed history is kept in `archive/*` tags. That is incorrect: no such tags exist. The former branch tips are retained on the single branch **`archive/branches-20261124`** (its `ARCHIVE.md` lists every former tip). Some commits are reachable only from that branch, for example `998c5bc` (pinned in `src/integration/F_SOURCE_PIN.json`) and `e76b08d` (referenced by `tests/platform/test_research_composed_negative_issue59.py`). The branch must be protected and must not be deleted. Removed files remain readable from Git history, for example `git show d6059af:docs/adminit-acceptance/DEPENDENCIES.md`.

The committed `repository-inventory.json` is a historical snapshot from before PR #102. It still lists the removed paths. It must be regenerated once, on the final integrated revision, with the command at the top of this document.
