# Architecture and repository

`src/api` provides the API, worker/supervisor composition and release lifecycle. `src/api/guardians` contains the Code, Data, Storage and Exchange proposal engines plus the common decision supervisor. Runtime transport remains the canonical ingest public transport rather than a second release-only exchange client. Durable state, leases, fencing and bounded retry decisions remain runtime contracts.

`src/ingest` supplies public historical-data ingestion; `src/storage` supplies storage primitives/migrations; `src/control`, `src/integration`, `src/analytics`, `src/backtest` and `src/strategy` hold integrated platform capabilities. `contracts` contains versioned DTO/schema contracts. `frontend` is the shipped static browser terminal; it has no application bundler or compilation command. Its exact Git blobs are deployed directly. Node/Playwright are development and browser-acceptance tools.

The release layout is `Setup-Tester.ps1`, `payload/`, `runtimes/python/`, `runtimes/postgres/`, `wheelhouse/`, `component-inventory.json`, `sbom.json`, `release-notes.md` and, after owner signing, `release-manifest.json`. All regular payload files except the envelope are covered by its signed SHA-256 map. The unsigned manifest and unsigned status sit outside that directory.

Private PostgreSQL uses one owned cluster with three dedicated databases: tester, tester_catalog and tester_research_release. Existing platform, storage/history projection, catalogue and research migration functions run under the installer owner; separate App roles receive runtime privileges without migration/DDL authority. The existing system cluster remains separate. Transactions, OHLCV/provenance/checksum checks, duplicate handling, interruption/replay and concurrent access require the dedicated PostgreSQL integration suite. A passing HTTP readiness response alone does not establish durable data acceptance.

The API schema and routes are defined by the source-bound FastAPI application and versioned contracts; retrieve `/openapi.json` from the accepted instance. Browser acceptance must cover instrument navigation, candles, history progress, results, worker state and recovery after API interruption. Public Bybit network access is environment-dependent; 403/429 and offline states require bounded retry and truthful errors.

`tests` contains regression and integration evidence. The historical evidence trees `docs/adminit-acceptance`, `docs/evidence`, `docs/physical-test` and `docs/coordination` were removed from the tree in PR #102. They remain readable from Git history (for example at `d6059af`) and on branch `archive/branches-20261124`. Pinned Guardian documents under `docs/guardians` remain in the tree. Old results do not certify any new release SHA.

The native reader/handler defaults to the existing reference-prices composition; the catalogue adapter supplies its distinct bounded public acquisition contract. Historical transport and catalogue DTO/retry ownership must not be conflated. The legacy root adapters (`bybit.py`, `bybit_history.py`) were removed in PR #102 without equivalence evidence; see [consolidation](consolidation.md).

Optional persisted research projection is composed before the static frontend catch-all by the existing API factory. It defaults off without an explicitly scoped research DSN. The existing worker delegates eligible ledger projections to the existing fenced dispatcher; no additional worker, engine, producer or retry executor is introduced. Claims, attempt exhaustion, grants and capabilities remain persisted and revocable. Provisioning its schema never publishes an artifact or enables real-market execution. Test artifacts remain explicitly synthetic; reader wiring and a successful projection are not real-market acceptance.

Restart reservations use the owner-controlled PostgreSQL policy scoped to installation UUID and source SHA. The App role cannot reset counters or replace authority with a runtime file. Host/API/worker diagnostics can be recorded in files, but recovery admission has no file-backed fallback. Policy changes and exhausted budgets require owner action; infrastructure unavailability is not permission to reset or bypass the budget.

Owner migrations now include `003_restart_budget.sql`, `004_transport_policy.sql` and `005_worker_instance.sql` in the existing platform database. Dedicated authority DSNs explicitly require SCRAM-SHA-256, pinned loopback and a non-5432 port. Transport authority is shared by catalogue acquisition and historical GETs through the existing adapter/connection boundary: each transmission reserves a durable token, 403/TLS security failures halt admission, and owner review is required to reset halted or abandoned state. There is no file-backed policy fallback, automatic expiry or public reset endpoint. See [runtime evidence and limits](runtime.md) for exact revisions and remaining race/acceptance gates.

Migration 005 binds worker heartbeats to the service instance captured by the API. A fresh heartbeat from the previous service instance cannot make a restarted API ready. Standalone legacy NULL-instance semantics remain separate from the native service profile.

Windows provisioning runs under the same unique App virtual-service identity in a demand-only actor phase. That actor creates the private venv and cluster outputs within the authenticated creation journal; immutable signed code remains read-only. The controller validates/seals actor output and transitions the same service to its bounded runtime role. Native actor/rollback acceptance is a separate CI gate; installing a service registration or producing a build ZIP is not evidence of the complete lifecycle.
