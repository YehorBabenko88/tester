# Проект: локальный терминал исторического анализа Bybit

Дата: 2026-11-07. Репозиторий: YehorBabenko88/tester. Ветка: workstream/d-ui.

## Цель и ограничения
Рабочий терминал для просмотра публичных данных и загрузки истории в существующий PostgreSQL. Только чтение публичных рынков; никакой торговли. Существующие raw_market и ingest_ranges сохраняются. Python 3.11+, Windows desktop, локальная привязка сервера к 127.0.0.1. Секрет подключения к БД остаётся на сервере.

## Подходы
Выбран пользователем: интерфейс и локальный API поверх существующего хранилища. Это даёт проверяемый сквозной сценарий и требует реализации серверных заданий.
Рассмотренная альтернатива: только UI с контрактом API. Проще изолировать работу другого агента, но сейчас нет сервера для проверки загрузок и графиков.
Выбор исполнителя: небольшой Python HTTP API и модульный браузерный клиент; зависимости и библиотека графиков определяются при реализации. Работы других веток не перезаписываются.

## Экран и сценарии
Тёмный адаптивный терминал: screener, Download Manager, графики, панель качества. Поиск и фильтр рынка, стабильный множественный выбор по category+symbol, сортировка с отсутствующими значениями в конце, сохранённый список в localStorage. Виртуализация строк, явные loading/empty/error состояния и повтор запроса.
Каждая метрика содержит value, unit, source, as_of, availability и причину отсутствия. Свежесть снимка отличается от времени получения ответа. Изменения за 1h/24h и волатильность вычисляются только по достаточной истории; формула и окно показываются. Капитализация отсутствует до подключения проверенного внешнего источника с однозначным соответствием активов.

## Локальный API и загрузки
API предоставляет инструменты/метрики, создание и чтение заданий, pause/resume/retry, качество и диапазоны графиков. Задание фиксирует набор category+symbol, источники, интервал и UTC-диапазон. Валидация ограничивает объём запросов, число инструментов и размер ответа; диапазоны проверяются до запуска работы.
Серверные рабочие процессы используют существующий загрузчик после выделения переиспользуемых функций; события и контрольные точки сохраняются. Pause действует между страницами, Resume продолжает с сохранённой точки, Retry повторяет только незавершённые части. Повторное получение записей безопасно благодаря ключам таблицы. После рестарта незавершённые задания восстанавливаются как приостановленные и требуют Resume.
Состояния: DISCOVERING, DOWNLOADING, VERIFYING, COMPLETE, PARTIAL, FAILED; отдельный признак paused. Иерархия: задание → инструмент → источник. Показываются полученные байты с определённой семантикой, обработанные и проверенные записи, скорость по измеренному времени, ошибки. Если объём неизвестен — неопределённый прогресс; 100% только после проверки всех запрошенных частей. ETA только при известном остатке и достаточном измерении скорости. Пустой ответ не доказывает полноту.

## Графики и агрегация
Candlesticks и синхронные панели Volume, OI, Funding, Mark/Index; VWAP и доступные производные индикаторы имеют обозначение derived. Zoom, pan, выбор диапазона запускают ограниченный запрос с отменой устаревшего ответа. Сервер агрегирует в подходящие временные корзины, ответ ограничен числом точек, миллионы тиков в браузер не передаются.
Footprint, Delta, CVD, Volume Profile и POC требуют достаточных сделок с объёмом и стороной агрессора. Если таких данных в хранилище нет, панели показывают недоступность с причиной. Нельзя выдавать оценку из OHLCV за подтверждённый footprint или delta. Поддержка вычисления этих панелей включается при наличии соответствующих подтверждённых данных; полнота покрытия указывается отдельно.

## Качество
Панель показывает покрытие диапазона, глубину истории, пропуски, текущую незакрытую свечу, непроверенные архивы, raw/derived и происхождение показателя. Хеш локально сохранённой записи означает проверку целостности, а не подтверждение полноты источника. Никаких вымышленных метрик или данных в рабочем режиме; тестовые fixtures используются только в тестах.

## Проверка и поставка
Проверить выбор нескольких инструментов между фильтрами и обновлениями, сортировку и сохранение списка; состояния загрузок, неизвестный знаменатель, частичный успех, ошибки API, pause/resume/retry и восстановление; синхронизацию графиков, отмену запросов, длинные диапазоны и ограничения точек; пропуски и raw/derived. Серверные тесты с контролируемыми upstream/БД и браузерные сценарии; отдельная проверка реального API при доступности. Недоступность PostgreSQL или Bybit явно сообщается, не заменяется фиктивным успехом.
Итог: коммиты в workstream/d-ui и Draft PR в main с командами проверки, результатами и известными ограничениями. Merge не выполнять.

## Оставлено исполнителю
Точные библиотеки, размеры панелей, формулы с документированием, разбиение модулей и миграции дополнительных таблиц заданий. Обязательная совместимость с существующими raw_market/ingest_ranges и доказуемость доступности важнее количества заполненных панелей.

## Уточнение интеграции с агентом E
Получен предложенный контракт FastAPI: envelope {schema_version: "1.0", data, next_cursor}; UTC epoch ms, end_ms exclusive, decimal strings, limit <= 1000. Download POST принимает {category,symbol,source,kind,interval,start_ms,end_ms}, ответ 202 содержит Job {id,state,progress,error,created_at,updated_at}; pause/resume/retry — POST. Без provider возвращается 503 provider_unavailable. Клиент следует этому контракту; серверные компоненты агента E переиспользуются после появления в репозитории, изменения его файлов без необходимости исключаются. Если интеграция ещё не доступна, UI использует адаптер контракта и явно показывает отсутствие сервера; заявлять сквозную готовность до подключения provider нельзя. Локальное подключение к PostgreSQL остаётся частью принятой цели.

## Approved implementation boundary (2026-11-07)
This section supersedes earlier proposals to implement backend in D. D owns frontend only. Agent A supplies trades; B persists/verifies; C computes all financial aggregates with Decimal; E serves the API. D must never implement a parallel ingestion/storage engine. All named panels are implemented renderers; no-record responses show DATA_UNAVAILABLE and a reason. Taker Buy/Sell is not Bid/Ask. Physical deployment and merge are not authorized.
