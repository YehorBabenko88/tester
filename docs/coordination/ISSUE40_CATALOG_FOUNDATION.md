# Issue 40 catalog foundation: opt-in, not native activation

This change is an independently testable backend slice. It does **not** complete Issue #40, change the installed 719b02e runtime, mount an API in `src.api.main`, change configuration, run migration, access PostgreSQL, or make trades.

`CatalogService(BybitCatalogSource())` owns complete public Bybit Trading catalog acquisition for linear/inverse separately. It follows explicit continuation cursors, refuses repeated/missing cursors, conflicting symbols and malformed category responses, and has page/row/body budgets. Only a fully exhausted catalog plus a valid ticker snapshot can replace a published snapshot. Failed attempt progress is separate; retained values become STALE, never fabricated zeros. Pagination exhaustion establishes current request-scope enumeration, **not historical listing coverage**. Expected total stays null because the endpoint supplies no total count.

The current scope requests `status=Trading`; contract type and settlement filters operate across that complete snapshot. Inactive/PreLaunch/status-specific acquisition is a follow-up gate. The source has one HTTP attempt with connect/read timeouts and an 8 MB decoded-body budget. HTTP429/Bybit10006 does not recurse or immediately retry: the backend poller applies exponential backoff (600/1200/1800 seconds after consecutive failures). Successful automatic cycles run every 300 seconds plus 0–15 seconds jitter. Manual signals coalesce and respect the source budget. Refresh calls for the same category cannot overlap. `stop()` sets cooperative cancellation before waiting for an in-flight HTTP call; it does not terminate a process. Requests have read-inactivity timeouts, not a promised hard wall-clock deadline under a continuously trickling peer.

The service is process-scoped; explicit production composition must ensure **one owner process**, not one poller per API worker. `start()` twice on the same service fails. No browser request starts a poller. A caller must start/stop it in application lifespan and apply the application's established local-host/origin/auth policy before exposing any future mutating refresh route. The included router is read-only.

`create_market_router(service)` provides `GET /api/market-catalog/{linear|inverse}`. Query: `search`, `contract_type`, `settle_coin`, `sort`, `direction=asc|desc|none`, `offset`, `limit<=500`, optional `revision`. Filtering and Decimal sorting cover the full snapshot before pagination; unavailable values are last in both directions, ties resolve by category/symbol. A revision mismatch is409 and requires restarting pagination. ETag includes freshness and failure state, so a retained revision becoming STALE does not incorrectly return304. Values carry endpoint, local observation time and exchange response time where supplied. Raw Bybit fractional `price24hPcnt` retains its native ratio units; it is not multiplied by100 at this boundary.

No volatility, one-hour price delta, OI deltas or market cap is invented. They remain UNAVAILABLE with a reason. Although the ticker endpoint exposes `prevPrice1h`, this slice deliberately requires separately reviewed timestamped observation/history qualification before publishing the requested 1h metric. Missing/invalid numeric ticker values are null. Source material: [Bybit instruments](https://bybit-exchange.github.io/docs/v5/market/instrument), [Bybit tickers](https://bybit-exchange.github.io/docs/v5/market/tickers), reviewed2026-11-08.

Remaining gates: persistent PostgreSQL observation snapshots and independently qualified deltas; inactive/status acquisition; multi-process scheduler ownership; mutable refresh API/origin authorization; unified accessible table and inline stable download-job binding; bulk selection, favorites, filters and13 timeframes; full local-API + test-owned-PG browser E2E without mocks; independent real Bybit enumeration evidence; review and pinned integration candidate before ADMINIT physical tests. No release-GO or Issue40 closure is claimed.
