2. **[P1] D promotes canonical UNAVAILABLE rows to drawable PARTIAL records and loses their reasons/provenance.** frontend/app.js:96 assumes every nonempty array has PARTIAL availability and no verification evidence, joining row.provenance with string coercion. Exact adaptSeries execution on an array row with availability={status:'UNAVAILABLE',reason:'source_conflict_fixture'} retained all candle rows, returned panel availability='PARTIAL', replaced reason with 'Coverage/verification not supplied by provider', and displayed source '[object Object]'. loadCharts:121-123 then draws these rows because it suppresses only DATA_UNAVAILABLE. Row-level canonical states must control renderability and keep reason/coverage/provenance inherited from the approved records; array presence cannot upgrade unavailable data. This is distinct from the older placeholder finding.

3. **[P2] D's metric adapter drops canonical unavailable reasons.** frontend/model.js:12-15 expects scalar m.availability and m.reason; Issue #8 availability is an object. An unavailable metric with availability={status:'UNAVAILABLE',reason:'missing_side_fixture'} yields generic 'Value, provenance or observation time not supplied', discarding the supplied reason. Align adapters with the canonical schema instead of requiring a parallel metric envelope, or document and validate a lossless adapter before rendering.
