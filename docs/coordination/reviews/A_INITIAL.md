## Findings

1. **P1 — Issue #1 is not implemented sufficiently to accept the workstream.** `src/ingest/archive.py:9-39` provides URL construction and a one-shot download only. The pinned recursive tree contains no source matrix, catalog component, REST ingestion component, tests, discovery implementation, or provenance documentation. `download` explicitly disclaims resume at line 19, deletes partial output on interruption (36-38), and has no retry/rate-limit handling. Issue #1 explicitly requires instrument catalog, historical REST sources, public archives, availability matrix, rate limits, resumable downloads, hashes, automated tests and documented provenance. The hash is implemented; the remainder cannot be inferred from a 39-line helper. Add component tests plus a persisted download job/manifest and explicit unavailable-source states before claiming acceptance. This is an acceptance gap, separate from the functional defects below.

2. **P1 — Archive success and replacement require no archive validation.** `src/ingest/archive.py:27-35` accepts every successful HTTP body, including empty bytes or HTML, and immediately replaces an existing destination. SHA-256 only fingerprints those bytes; it does not establish that they are a usable gzip/CSV archive. An executed fake HTTP 200 HTML response replaced a previous destination and returned successful path/bytes/hash/source metadata. A successful server or proxy error page can therefore destroy a valid cached archive and be reported as success. Validate nonempty bytes, gzip EOF/CRC and accepted archive schema before replacement; test HTML, zero body, truncated gzip, wrong schema and preservation of an existing destination on each rejection.

3. **P1 — Sparse observations become permanently cached as complete.** Baseline `engine.py:126-128` assigns complete solely because any records exist and the range is more than a day old; there is no expected timestamp/continuity/availability check. At `engine.py:94-95`, subsequent runs skip that entire range. An executed fake client returning exactly one valid OI point for a day of 5min requests produced `complete`, leaving the missing history unrepairable through normal reruns. Bybit documents account-ratio recording periods and explicitly notes delayed data delivery, so page exhaustion does not establish continuity. Validate each regular sampling schedule against expected timestamps or retain incomplete/unknown coverage when not provable; distinguish unavailable historical periods from complete periods. Test one-record days, interior gaps, delayed records and reruns that recover them.

4. **P1 — Archive retries can certify rows from different archive versions under one hash.** Baseline `engine.py:189-196` commits every 1,500 trades and uses `ON CONFLICT DO NOTHING`. On retry, corrected rows with the same IDs retain their old values. The only reconciliation is total row count (`198-200`), then `trade_files.sha256` is overwritten with the new file hash (`201-205`). A failure after batch one followed by a corrected archive with the same IDs/count can thus finish complete while persisted prices/sizes/raw rows differ from the archived bytes named by the provenance hash. This also affects a retry of any failed historical import. Stage imports per file/version and publish atomically, or validate/update every colliding trade before certifying; test failure after a committed batch, a same-ID changed price on retry, and a same-count replaced ID.

5. **P1 — Failed archive rows remain eligible for production aggregates.** The partial commits above survive malformed later rows, CRC errors and other import failures. `engine.py:208-210` merely sets error coverage and removes the local partial file. `engine.py:231` aggregates every trade for the category/symbol, with no complete-coverage or successfully published file requirement. Building clusters after a failed archive therefore publishes incomplete footprints/delta. Use atomic staging or restrict aggregation to imports whose data and manifest have been successfully published. Test a 1,501-row archive with a malformed last row and assert no partial-day cluster output is exposed.

6. **P2 — Current instrument catalog silently excludes inactive historical instruments.** Baseline `bybit.py:63-77` queries instruments without any status filter, and there is no historical catalog path. Bybit describes the endpoint as online pairs and documents a default Trading/PendingOpen filter for derivatives. Thus this cannot be presented as the complete instrument universe for historical collection; expired/delisted archive symbols need separate discovery/availability. Label the current catalog scope and reconcile available archive symbols, preserving status/source/as-of metadata. Test an archive-only symbol and ensure it can still be selected for historical ingestion. Baseline `bybit_history.py:29-36` also always sends limit/cursor for spot despite the documented lack of spot pagination support; `bybit.py:67-69` already avoids that legacy behavior.
