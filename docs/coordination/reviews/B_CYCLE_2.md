## Findings

**P1: Issue #14 lifecycle controls are not implemented at this head.** The complete src/storage package has models, archives, bootstrap, migration, coverage, CLI and Store; CLI supports doctor/migrate/bootstrap only. There are no RAW_PROTECTED/VERIFIED_ARCHIVE/DERIVED_REBUILDABLE/CACHE/TEMP retention classifications, mark-and-sweep dry-run, size forecast, low-disk acquisition pause, reference-aware pruning, bounded integrity scanner, per-table size/row/scan/discrepancy metrics, disk/WAL/checkpoint/autovacuum monitor or backup RPO/RTO. Existing archive hash checks, repair queue and documented dump/restore instructions implement part of the requirement, not lifecycle acceptance. This is missing scope relative to the newly assigned #14, not a claim that PR #13 deletes data or regresses a previously implemented lifecycle controller. Keep #14 open and NOT_READY.

**P1: required ingestion-run provenance is not captured per source observation.** models.py 55-61 accepts source with only url/fetched_at, implicitly defaults precision to ms and accepts no ingestion_run/source_kind. Executed normalize(trade()) succeeds using B's fixture with just url/fetched_at. Store.ingest 137-140 stores `(record_key,source,raw_envelope)` without job_key/evidence_id/run relation; the evidence ledger has job identity but does not map record_sources to that ledger. Replaying one same source envelope in distinct ingestion jobs is deduplicated into one source observation because source_id excludes job. An adapter can require source_kind/ingestion_run/timestamp_precision on all future writes, but cannot reconstruct authentic historical per-record run identity merely from an arbitrary source hash or a new read-time UUID. Add explicit source-observation → ingestion-run/evidence relation or preserve/validate these required source fields at ingress, and test two-run replay provenance.

**Integration gate: Store.read is a storage representation, not E's approved trade JSON.** store.py 224-242 returns raw_records plus one source selected by `ORDER BY source_id LIMIT 1`; it does not return all append-only source observations, normalized provenance, availability/coverage or evidence_refs. Executed its actual conversion code with an injected synthetic DB row (no actual PG read); shared validate_record('trade',row) fails with required provenance, availability, coverage, quantity and taker_side missing; internal content_hash/dataset/interval/payload/record_key/size/source are forbidden extra fields. This is primarily an explicit E/B adapter obligation, not proof that internal SQL representation must equal HTTP JSON. Adapter must select/rename payload.size→quantity and payload.side→taker_side, omit internal columns, include all relevant authentic provenance, and map Store.coverage conservatively. A bare field rename or optimistic AVAILABLE/COMPLETE default is insufficient. Store.coverage currently emits range lists and a boolean, with no evidence references in its returned object; fetch evidence IDs from the durable ledger. For source us precision, convert exact timestamp_us to the shared ns string only when source-provided microseconds genuinely exist; preserve source precision='us'. For composite_v1 IDs, map to shared id_origin='synthetic' with identity_method and retain incomplete coverage.

**P2: recovery scheduler has no exclusive fetch claim.** Store.recover reads next_attempt_ms, then increments attempt_count in a separate transaction without FOR UPDATE/SKIP LOCKED or atomic compare-and-set, and network fetch occurs outside the ingestion lock. Two workers can fetch the same due job concurrently; after one successful verified ingest, the other's late fetch failure can update state='retry' and next_attempt_ms. Scope locks protect atomic raw publication but do not protect this scheduler state transition. Static finding; not reproduced against PG in this sandbox. Add claim/lease or conditional attempt token and test a late failure against another worker's success.
